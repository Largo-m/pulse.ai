# ADR-001: UI-only MVP with full shell parity and placeholder CTAs

## Status

Accepted

## Date

2026-05-14

## Context

The first milestone for the Agentic Governance Command Center targets the Orchestrator empty state from Stitch. Stakeholders want visual and structural parity with the provided design while deferring real Git mounting and remote synchronization. The primary persona is a platform engineer or repository owner who will eventually configure workspaces and connect Git, but integrations are out of scope for this release.

## Decision

Ship the full command center shell (top bar, workspace breadcrumb lane, standby status, centered empty state, dual CTA cards, and footer chrome) matching the Stitch reference. Primary calls-to-action remain visible and discoverable; until integrations exist, they provide non-destructive feedback (for example, a clear “coming soon” or equivalent in-product message) rather than performing side effects.

## Alternatives Considered

### Alternative 1: Disabled CTAs with explanatory copy

- **Description**: Same layout, but CTAs are disabled with helper text about future capability.
- **Pros**: Sets clear expectations; reduces perceived broken behavior.
- **Cons**: Weaker activation energy and less representative of the intended end-state interaction model.
- **Why rejected**: Stakeholders preferred keeping CTAs active with lightweight placeholder feedback to preserve the designed affordances.

### Alternative 2: Phased shell (center first)

- **Description**: Implement the central empty state first and align the outer chrome later with the existing Flutter shell.
- **Pros**: Faster initial milestone; less surface area.
- **Cons**: Dilutes the “command center” first impression and splits design review across releases.
- **Why rejected**: Visual parity with the reference shell was prioritized for this milestone.

## Consequences

### Positive

- Users immediately recognize the intended operating environment and future actions.
- Design and product can validate layout, hierarchy, and copy in a realistic frame.
- Clear separation between presentation milestone and future integration work.

### Negative

- Without careful copy, active CTAs can feel misleading; placeholder feedback must be obvious and trustworthy.
- Larger UI surface to maintain before backend value exists.

### Risks

- **Risk**: Users interpret placeholder feedback as errors.
  - **Mitigation**: Use neutral, explicit language and consistent placement for “not yet available” states.
