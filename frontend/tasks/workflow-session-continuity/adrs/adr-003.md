# ADR-003: Cloud Run Status Reconciliation on Workflow Open

## Status

Accepted

## Date

2026-05-22

## Context

Users may close the app while a PRD run is `running` in Hive. On reopen, local state shows `running` workflow phase but `PrdWorkflowCubit` has no `activeRunId` or SSE subscription. The agent may have finished in the cloud while the app was away, leaving a stale in-progress UI and blocking restore of the true last finalized session.

## Decision

During PRD workflow bind, if the latest run for the workflow is non-terminal and has a `cloudRunId`, call a new `CursorPrdAgentService.fetchRunStatus` (GET) to reconcile cloud status. When cloud reports a terminal outcome, update `PrdRunEntity` and workflow phase via existing fail/complete use cases or a slim `ReconcilePrdRunStatusUseCase`, then proceed with restore of that run if it became terminal. If cloud still reports active, emit in-progress-only session mode without logs.

## Alternatives Considered

### Alternative 1: Local Hive only

- **Description**: Trust local `running` until user starts/cancels.
- **Pros**: No new API surface.
- **Cons**: Stale in-progress after offline completion; violates PRD mitigation.
- **Why rejected**: User selected cloud refresh.

### Alternative 2: Manual “Refresh status” button only

- **Description**: User-triggered reconciliation.
- **Pros**: No automatic network on every open.
- **Cons**: Easy to miss; poor cold-start experience.
- **Why rejected**: User selected automatic reconciliation on open.

### Alternative 3: Resume SSE `watchRun` on open

- **Description**: Reattach stream and backfill.
- **Pros**: Live updates.
- **Cons**: Conflicts with in-progress-only MVP; partial replay risk.
- **Why rejected**: PRD defers live catch-up.

## Consequences

### Positive

- Closes stale in-progress gap after app restart.
- Enables restore immediately after silent cloud completion.

### Negative

- Requires new HTTP method, tests, and failure handling on every open with active cloud run.
- Adds latency to open path (network bound).

### Risks

- Cursor API shape drift — isolate mapping in `CursorPrdAgentServiceImpl`; fake service for tests.
- Network failure during reconcile — treat as in-progress locally and surface non-blocking connection state; do not fake restore.

## Implementation Notes

- Proposed endpoint: `GET /v1/agents/{agentId}/runs/{runId}` returning status enum mappable to `PrdRunStatus`.
- Gate on successful `PrdRunConnectionGate` / credential presence; skip cloud call if missing credential (stay local in-progress).
- On reconcile failure, keep ADR-001 in-progress rules; optional retry via existing connection banner flow.
