# ADR-004: Restore Presentation and Buffer Policy

## Status

Accepted

## Date

2026-05-22

## Context

Technical clarification resolved open PRD questions: failed/cancelled runs restore fully; histories cap at 200 events; no trust banner; starting a new run keeps restored content visible with an in-progress overlay banner.

## Decision

1. **Event cap**: When hydrating stream events, keep the last `PrdStreamBufferPolicy.maxInMemoryEvents` (200) events ordered by `sequence` for both terminal and conversation projections.
2. **Failed/cancelled**: Same restore contract as `completed` (full terminal + derived conversation + artifacts).
3. **New active run**: Do not clear restored snapshot fields on `startRun`. Show a PT-BR banner indicating a new run is in progress; live stream panel stays empty/in-progress-only until the new run completes (no partial live replay in MVP).
4. **Trust banner**: No “Restored from run on …” banner in MVP (implicit restore).

## Alternatives Considered

### Alternative 1: Load all events

- **Description**: No cap on restore.
- **Pros**: Complete audit trail.
- **Cons**: Risk >5s perceived load; large widget rebuilds.
- **Why rejected**: User chose 200-line cap.

### Alternative 2: Clear restored UI on new `startRun`

- **Description**: Reset panels when starting a run.
- **Pros**: Simpler single `streamLines` list.
- **Cons**: Loses context during overlapping review + run.
- **Why rejected**: User chose keep-with-banner.

### Alternative 3: Restore banner

- **Description**: Show run timestamp banner.
- **Pros**: Extra trust signal.
- **Cons**: UI noise; PRD open question unresolved product-wise.
- **Why rejected**: User chose implicit restore.

## Consequences

### Positive

- Predictable memory and render cost on desktop.
- Clear UX when starting another run without wiping prior session.

### Negative

- Older log lines beyond 200 are only on disk/JSONL, not in UI until Phase 3 pagination.
- `PrdWorkflowState` gains separate restored vs live fields (slightly more state complexity).

### Risks

- Users with long runs may not see earliest lines — document in release notes; JSONL remains full audit path.

## Implementation Notes

- Add `PrdSessionViewMode` enum to `PrdWorkflowState`: `empty`, `restored`, `inProgressOnly`, `restoreFailed`, `restoredWithActiveRun`.
- Strings for banner and errors live in `OrchestratorStrings` (PT-BR).
