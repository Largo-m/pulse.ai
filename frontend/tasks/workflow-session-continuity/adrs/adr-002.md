# ADR-002: Conversation Derived from Stream Events

## Status

Accepted

## Date

2026-05-22

## Context

The PRD requires user prompts and agent responses for the same restored run. The codebase has no `ConversationMessage` entity. `StreamEventEntity` already captures `assistant`, `thinking`, `tool_call`, `result`, and related types during runs. `PrdRunEntity` stores optional `feedback`; user directive lives on `WorkflowEntity.directive` only.

## Decision

Derive conversation UI for restore (and live runs) from persisted stream events plus run-level `feedback` and `workflow.directive`. Map selected event types (`assistant`, `result` with user-visible payload) into `PrdConversationMessageUiModel` bubbles. User-side messages: primary bubble from `workflow.directive` when non-empty; append `run.feedback` when present for that run. Do **not** add a new Hive box or dual-write transcript table in MVP.

## Alternatives Considered

### Alternative 1: Persist `directive` on `PrdRunEntity`

- **Description**: Store per-run directive at `createRun`.
- **Pros**: Accurate historical prompt when directive changes between runs.
- **Cons**: Schema migration; extra write on every start.
- **Why rejected**: User chose derive-from-current model; document limitation instead.

### Alternative 2: Dedicated `ConversationMessage` Hive box

- **Description**: Append messages at stream ingest time.
- **Pros**: Clean domain model; easy querying.
- **Cons**: Dual-write complexity; redundant with stream log.
- **Why rejected**: YAGNI for MVP given existing event store.

### Alternative 3: Terminal-only restore (no conversation)

- **Description**: Restore logs only in MVP.
- **Pros**: Fastest delivery.
- **Cons**: Fails PRD user stories.
- **Why rejected**: Out of scope for product acceptance.

## Consequences

### Positive

- No Hive schema change for conversation.
- Single source of truth: stream events already written by `AppendStreamEventUseCase`.

### Negative

- If `workflow.directive` changes after a run, restored user bubble may not match the original prompt (document in TechSpec risks).
- `thinking` / `tool_call` events are terminal-oriented, not conversation bubbles (by design).

### Risks

- Sparse `payloadSummary` on old events yields generic labels — reuse `_displayTextForEvent` mapping from cubit via shared mapper.

## Implementation Notes

- Extract `PrdStreamEventMapper` (domain or presentation) shared by live stream handler and restore use case.
- Conversation list capped with `PrdStreamBufferPolicy.maxInMemoryEvents` (ADR-004).
