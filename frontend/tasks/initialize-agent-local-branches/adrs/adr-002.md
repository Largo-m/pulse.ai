# ADR-002: git2dart (libgit2) for Local Branch Enumeration

## Status

Accepted

## Date

2026-05-18

## Context

The initialize-agent modal must list local Git branches and resolve HEAD from `LocalProjectEntity.absolutePath` on desktop without network access. The orchestrator already isolates platform IO behind `domain/service` interfaces with implementations in `features/orchestrator/service/`.

## Decision

Use the **`git2dart`** package (libgit2 bindings) in `LocalGitBranchesServiceImpl`:

- Open the repository with `Repository.open(absolutePath)`.
- Enumerate local branches via `repository.branchesLocal`.
- Resolve the current branch name from `repository.head` (and `isHeadDetached` when needed).
- Map libgit2/git2dart failures to typed outcomes (`notGitRepository`, `failure`) without surfacing raw SDK strings in the UI.

Add `git2dart` to `pubspec.yaml` (pin latest stable compatible with SDK `^3.10.4`).

## Alternatives Considered

### Alternative 1: `Process.run('git', ...)`

- **Description**: Shell out to the system `git` binary with `for-each-ref` and `symbolic-ref`.
- **Pros**: No native library in the app bundle; familiar Git CLI semantics.
- **Cons**: Depends on user PATH and installed Git version; harder to test deterministically; process spawn overhead.
- **Why rejected**: Stakeholder chose libgit2 integration for consistent in-process behavior.

### Alternative 2: Manual `.git` filesystem parsing

- **Description**: Read `HEAD` and `refs/heads/*` without libgit2 or CLI.
- **Pros**: Zero native deps.
- **Cons**: Incomplete Git edge cases (worktrees, packed-refs, ambiguous states); high maintenance.
- **Why rejected**: Fragile compared to libgit2.

## Consequences

### Positive

- Branch list and HEAD resolution align with Git semantics.
- Service remains mockable via interface + injectable repository opener in tests.

### Negative

- Native libgit2 artifacts increase app size and require `flutter pub get` / platform rebuild on all desktop targets.
- Package must be validated on macOS, Windows, and Linux CI/dev machines.

### Risks

- `Repository.open` may fail on valid folders that are not Git roots — map to `notGitRepository`.
- Detached HEAD may not match any local branch name — handled in TechSpec (no default selection; submit stays disabled until user picks a branch).

## Implementation Notes

- Keep `git2dart` imports only in `service/` implementation, never in `domain/` or `presentation/`.
- Dispose or free repository resources per call (try/finally) to avoid leaks on repeated project switches.
- Branch ordering: preserve `branchesLocal` order (no sort).
