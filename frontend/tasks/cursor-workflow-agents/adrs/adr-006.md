# ADR-006: Stable Mapped Project Identity via UUID (Recent Projects v2)

## Status

Accepted

## Date

2026-05-20

## Context

`LocalProjectEntity.id` is currently the normalized absolute filesystem path. ADR-003 and the PRD require artifact association to survive re-import and path changes where possible. Workflow artifacts in Hive and on disk will key exclusively on `projectId`.

## Decision

Introduce **Recent Projects document v2** with a persisted **UUID `projectId`** assigned on first successful import. Maintain a secondary **`canonicalPath`** (normalized absolute path) for sandbox, Git, and picker resolution. On re-import of the same path (or detected path update policy), resolve to the existing UUID when `canonicalPath` matches a known mapping; new paths create new UUIDs.

Migrate v1 documents: for each stored project, generate UUID, set `canonicalPath` from former id field, rewrite `activeProjectId` to UUID.

## Alternatives Considered

### Alternative 1: UUID for New Projects Only

- **Description**: Legacy path-as-id rows coexist with UUID rows.
- **Pros**: Smaller migration blast radius.
- **Cons**: Two identity schemes; artifact repos must branch; pilot confusion.
- **Why rejected**: Tech lead clarification chose full v2 migration for MVP.

### Alternative 2: Defer UUID (Path-as-Id for MVP)

- **Description**: Ship PRD store with path keys; migrate later.
- **Pros**: Fastest short-term.
- **Cons**: Directly conflicts with ADR-003 risk mitigation and re-import stories.
- **Why rejected**: Artifact store depends on stable keys from day one.

## Consequences

### Positive

- Workflow and artifact bundles remain addressable after folder moves if path remapping rules are applied.
- Sidebar and Hive foreign keys use opaque ids, not user-visible paths.

### Negative

- One-time migration logic and tests on `RecentProjectsDocument`.
- Duplicate imports of copies at different paths create distinct UUIDs (expected; product may later offer merge).

### Risks

- Migration failure on upgrade; mitigation: backup v1 JSON before rewrite, fail closed with user-visible error.

## Implementation Notes

Bump storage key or `schemaVersion` in `recent_projects_document.dart`. Update all use cases and tests referencing path-as-id.
