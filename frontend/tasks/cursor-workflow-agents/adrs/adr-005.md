# ADR-005: Hive-Indexed Artifact Store with Filesystem Markdown Blobs

## Status

Accepted

## Date

2026-05-20

## Context

ADR-003 mandates Pulse-internal storage keyed by mapped project id and workflow slug, including PRD body, ADRs, run metadata, approval state, and stream history. `path_provider` is available but unused; `SharedPreferences` already stores recent projects JSON and must not hold large documents or high-volume stream events.

## Decision

Adopt a **two-tier store**:

1. **Hive** — Index and operational data: workflow registry per project, slug uniqueness, PRD phase status, run records, approval metadata, stream event index (timestamps, sequence, run id), and pointers to blob paths.
2. **Filesystem** (via `path_provider`) — Content blobs under a stable app data root, e.g. `{appSupport}/pulse/workflows/{projectId}/{slug}/` with `prd.md`, `adrs/*.md`, and optional `streams/{runId}.jsonl` for archival chunks if not fully inlined in Hive.

Resolution APIs use **project id + slug** only; presentation never reads arbitrary paths.

## Alternatives Considered

### Alternative 1: Filesystem Only

- **Description**: JSON sidecars per slug directory for metadata and runs.
- **Pros**: No new database package; easy manual inspection.
- **Cons**: Weak querying for workflow lists and slug collision checks; race-prone concurrent writes.
- **Why rejected**: Sidebar workflow list and run status need fast indexed queries.

### Alternative 2: SQLite via drift

- **Description**: Relational schema with typed migrations.
- **Pros**: Strong queries and migrations.
- **Cons**: Additional codegen and SQL expertise for a single-feature MVP index.
- **Why rejected**: Stakeholder chose Hive for index layer during TechSpec clarification.

### Alternative 3: All Content in Hive

- **Description**: Store PRD markdown and ADRs as Hive values.
- **Pros**: Single persistence mechanism.
- **Cons**: Large documents and stream volume inflate box size; harder diff/review tooling.
- **Why rejected**: Markdown review and export-friendly layout favor files on disk.

## Consequences

### Positive

- Fast workflow listing for `RecentProjectsSidebar` without scanning directories.
- PRD/ADR files remain human-inspectable under app support for support/debug.
- Clear separation: Hive for queries, disk for documents.

### Negative

- Must keep Hive records and filesystem paths consistent on write (transactional outbox or write-order discipline).
- Backup story spans Hive boxes and directories (document in product copy).

### Risks

- Orphan files if Hive write fails mid-operation; mitigation: write temp file then commit Hive pointer, or delete-on-rollback in repository impl.

## Implementation Notes

Register Hive adapters in `data/` layer. `ArtifactRepository` and `WorkflowRepository` coordinate box updates and file IO. Do not store API keys or tokens in either tier.
