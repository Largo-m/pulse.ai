# ADR-002: PRD-Only MVP Scope

## Status

Accepted

## Date

2026-05-19

## Context

ADR-001 established a native Pulse cockpit for Cursor-powered workflow orchestration. Stakeholders narrowed delivery scope to validate the run → stream → review → approve pattern on the PRD phase before extending to TechSpec, Tasks, execution, QA, and Review.

## Decision

Limit this initiative’s **MVP to the PRD phase only**. Pulse will integrate Cursor for a **PRD specialist agent**, live execution streaming, human approval of the PRD document, and persistence of PRD content and ADRs **inside Pulse** under mapped project + slug (see ADR-003). Later pipeline phases are deferred to future PRDs.

## Alternatives Considered

### Alternative 1: Full Pipeline MVP

- **Description**: Ship PRD through Review in one release.
- **Pros**: End-to-end story immediately.
- **Cons**: High delivery risk; many failure modes; harder to validate UX before repeating it.
- **Why rejected**: Scope too large for a focused first Cursor integration.

### Alternative 2: Thin PRD Trigger Only (No Approval UX)

- **Description**: Button to start PRD agent; artifact saved without in-app review/approve.
- **Pros**: Smallest build.
- **Cons**: Misses accountability gate; weak differentiation from running agents outside Pulse.
- **Why rejected**: Does not meet approval and streaming requirements.

## Consequences

### Positive

- Faster learning on streaming, Cursor connection, and Pulse-side artifact approval.
- Clear milestone for TechSpec (Phase 2) reusing the same storage and UX pattern.
- Simpler success metrics (PRD cycle time only).

### Negative

- Downstream phases unavailable in Pulse until follow-up work ships.
- UI may need locked or “coming soon” states after PRD.

### Risks

- Perceived incompleteness; mitigation: PRD-first roadmap in product copy.
- PRD workspace may need extension for later phases; mitigation: design as template for future phases.

## Implementation Notes

See `_prd.md`. TechSpec and subsequent phases are out of scope for this document.
