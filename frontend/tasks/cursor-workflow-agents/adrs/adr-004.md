# ADR-004: Hybrid Cursor Runtime for PRD Agent Execution

## Status

Accepted

## Date

2026-05-20

## Context

ADR-001 requires Pulse to orchestrate Cursor specialist agents with in-app live streaming. The codebase has local Git branch resolution and macOS sandbox access for mapped projects but no Cursor integration. Stakeholders need PRD agent runs anchored to the correct local repository while keeping orchestration and secrets inside Pulse.

## Decision

Use a **hybrid integration model** for the PRD specialist agent:

1. **Cloud side** — Cursor SDK / Cloud Agents API for agent lifecycle (queue, run, cancel), credential-backed connection, and execution event streaming (SSE or equivalent) into Pulse.
2. **Local side** — Existing orchestrator services supply execution context: mapped `projectId`, normalized repo path, selected Git branch, workflow slug, and feature directive. Pulse never embeds secrets in streams or stored artifacts.

Pulse maps cloud run identifiers to local workflow records in Hive and persists stream events and artifacts under project + slug (ADR-003, ADR-005).

## Alternatives Considered

### Alternative 1: Local CLI Subprocess Only

- **Description**: Spawn Cursor CLI with repo as working directory; parse stdout/stderr for stream UI.
- **Pros**: No cloud dependency; aligns with local-first desktop story.
- **Cons**: Fragile parsing; unclear cancel/stream contracts; harder to align with specialist agent product surface.
- **Why rejected**: Higher integration risk and weaker alignment with documented Cloud Agents streaming APIs.

### Alternative 2: Cloud-Only (No Local Context Service)

- **Description**: Pass raw paths in API payloads from presentation layer.
- **Pros**: Fewer Pulse services.
- **Cons**: Duplicates Git/sandbox logic; leaks path handling into UI; harder to test and evolve context assembly.
- **Why rejected**: Violates Clean Architecture boundaries already established in `orchestrator`.

## Consequences

### Positive

- Reuses `LocalGitBranchesService` and project mapping for trustworthy branch/repo context.
- Streaming and run states align with product run model (`queued`, `running`, `completed`, `failed`, `cancelled`).
- Secrets stay in secure storage / OS keychain patterns, not in Hive or markdown files.

### Negative

- MVP depends on network availability for agent runs.
- Pulse must implement connection onboarding, retry policy, and error surfacing for cloud failures.

### Risks

- API surface changes on Cursor side; mitigation: isolate behind `CursorPrdAgentService` port in `domain/service/`.
- Pilot teams without cloud access; mitigation: preflight connection status before enqueueing runs.

## Implementation Notes

Implement `CursorPrdAgentService` in `lib/features/orchestrator/domain/service/` with impl in `service/`. Composition root wires HTTP client and local context builder. See `_techspec.md` Integration Points.
