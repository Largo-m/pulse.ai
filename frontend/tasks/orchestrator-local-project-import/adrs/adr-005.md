# ADR-005: OrchestratorPage on Existing Orchestrator Route

## Status

Accepted

## Date

2026-05-15

## Context

`OrchestratorEmptyPage` is registered at `RoutePaths.orchestrator`. MVP adds conditional sidebar while preserving empty body when no workspace UI exists. GoRouter migration is planned but not active.

## Decision

- Rename `OrchestratorEmptyPage` → **`OrchestratorPage`** (same file path may become `orchestrator_page.dart`).
- Keep **`RoutePaths.orchestrator`** unchanged; update `ShellNavigatorRoutes` builder only.
- Layout: `Row` with optional `RecentProjectsSidebar` when `RecentProjectsCubit` state has `projects.isNotEmpty`; existing breadcrumb + empty body in expanded column.
- Update `shell_navigator_routes_test.dart` to expect `OrchestratorPage`.

## Alternatives Considered

### Alternative 1: Keep OrchestratorEmptyPage name

- **Description**: Add sidebar inside class named "Empty".
- **Pros**: Fewer import churn references.
- **Cons**: Misleading name after sidebar ships.
- **Why rejected**: Team chose accurate naming.

### Alternative 2: OrchestratorShell extraction

- **Description**: Separate shell widget for chrome + sidebar slot.
- **Pros**: Smaller page file.
- **Cons**: Extra abstraction for MVP.
- **Why rejected**: YAGNI; can extract in Phase 2 when workspace body arrives.

## Consequences

### Positive

- Single route for orchestrator; no new routes for sidebar.
- Tests and deep links remain stable.

### Negative

- One-time rename churn in router test and imports.

## Implementation Notes

- Wrap `OrchestratorPage` with `MultiBlocProvider` for `RecentProjectsCubit` (and listen to `ImportFlowCubit` only on import page, or provide both above shell navigator if needed).
