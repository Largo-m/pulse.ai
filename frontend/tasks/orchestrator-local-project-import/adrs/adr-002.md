# ADR-002: shared_preferences for Recent Projects Persistence

## Status

Accepted

## Date

2026-05-15

## Context

MVP requires local persistence of up to ten recent projects and the active project id across app restarts. No sync, no cloud, no repository content indexing. The codebase has no persistence layer today; `path_provider` is available but unused.

## Decision

Persist a single JSON document in `shared_preferences` under a versioned key (e.g. `orchestrator.recent_projects.v1`). The document contains:

- `projects`: array of `{ id, absolutePath, displayName, lastAccessedAtIso }`
- `activeProjectId`: nullable string

Repository implementation serializes/deserializes via `RecentProjectsRepositoryImpl`. Add `shared_preferences` to `pubspec.yaml`.

## Alternatives Considered

### Alternative 1: JSON file via path_provider

- **Description**: Write `recent_projects.json` to application support directory.
- **Pros**: Easier manual inspection; no size concerns for larger payloads later.
- **Cons**: Extra file IO abstraction; second persistence pattern if prefs used elsewhere later.
- **Why rejected**: Team chose shared_preferences for MVP simplicity at ≤10 items.

### Alternative 2: Hive / Isar

- **Description**: Local database with typed boxes.
- **Pros**: Scales to richer project metadata in Phase 2–3.
- **Cons**: New dependency and migration story for a tiny list.
- **Why rejected**: YAGNI for MVP scope.

## Consequences

### Positive

- Minimal infrastructure; fast to ship.
- Atomic read/write of list + active id in one payload.

### Negative

- Entire document rewritten on each change (acceptable for ≤10 items).
- Not human-readable on disk without tooling.

### Risks

- Corrupt JSON — mitigate with schema version, defaults to empty list on parse failure, and unit tests.

## Implementation Notes

- `RecentProjectsLocalStorage` adapter wraps `SharedPreferences` get/set string.
- Use `dart:convert` for JSON; ISO-8601 strings for timestamps.
- Cap enforcement and sort in domain use cases, not in the adapter.
