# ADR-003: Split Cubits for Recent Projects and Import Flow

## Status

Accepted

## Date

2026-05-15

## Context

The orchestrator screen needs hydrated recent projects, active selection, and a transient import flow (picker loading, cancel, error). `flutter_bloc` is a project dependency but unused. Repository rules prefer Bloc/Cubit over `setState` for user-visible state.

## Decision

Use two cubits:

1. **`RecentProjectsCubit`** — owns list hydration, active project id, `selectProject`, and `refresh` after successful import.
2. **`ImportFlowCubit`** — owns import-in-progress, success path, cancel, and failure message key for UI.

`ImportFlowCubit` invokes `ImportLocalProjectUseCase` (picker + repository). On success, the **page** calls `Navigator.popUntil` to orchestrator and `RecentProjectsCubit.refresh()`.

Provide both cubits at the shell level or via a parent that wraps orchestrator and import routes so import page can access `ImportFlowCubit`.

## Alternatives Considered

### Alternative 1: Single OrchestratorCubit

- **Description**: One cubit for list, active, and import states.
- **Pros**: Fewer providers; simpler dependency graph.
- **Cons**: Large state object; import route couples to unrelated list logic.
- **Why rejected**: Team preferred clearer boundaries for MVP.

### Alternative 2: ValueNotifier in pages

- **Description**: Local notifiers without Bloc.
- **Pros**: Less boilerplate.
- **Cons**: Conflicts with project architecture rules; harder to unit test.
- **Why rejected**: Explicit team choice for Bloc pattern.

## Consequences

### Positive

- Import flow testable in isolation.
- Recent list refresh explicit after import.

### Negative

- Page coordinates navigation + refresh (orchestration in presentation).
- Two `BlocProvider`s to wire.

### Risks

- Missed refresh after import — mitigate with integration-style cubit tests and a single success handler in `ImportProjectSelectSourcePage`.

## Implementation Notes

- Add `bloc_test` to `dev_dependencies`.
- Register use cases and repository in composition (constructor injection from `main.dart` or future `app/di`).
