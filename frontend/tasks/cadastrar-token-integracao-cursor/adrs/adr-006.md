# ADR-006: Settings Orchestration in CursorConnectionCubit

## Status

Accepted

## Date

2026-05-22

## Context

Settings needs test/save/remove orchestration tied to global connection status. Introducing a second cubit increases synchronization bugs (save succeeds but banner stale). `ValueNotifier`-only local state avoids bloc tests but pushes validation orchestration into widgets.

## Decision

Extend `CursorConnectionCubit` and `CursorConnectionState` with settings-session fields (`isDraftTestPassed`, `settingsStatus` enum: idle/testing/saving/removing, `settingsErrorMessageKey`). Methods: `resetSettingsSession()`, `testDraftCredential(String)`, `saveDraftCredential(String)`, `removeCredential()`. Inject `ValidateCursorCredentialUseCase`, `SaveCursorCredentialUseCase`, `RemoveCursorCredentialUseCase` alongside existing preflight use case.

## Alternatives Considered

### Alternative 1: Dedicated `CursorIntegrationSettingsCubit`

- **Description**: Separate cubit provided only to the modal.
- **Pros**: Smaller single-purpose class.
- **Cons**: Must sync two cubits after save/remove; duplicate preflight triggers.
- **Why rejected**: User chose extend connection cubit.

### Alternative 2: Widget-local ValueNotifier only

- **Description**: No bloc for settings.
- **Cons**: Harder to unit test; violates project bloc preference for user-visible flows.
- **Why rejected**: Inconsistent with orchestrator patterns.

## Consequences

### Positive

- Single source of truth for connection + settings operations.
- Existing `BlocProvider` in composition tree covers the modal.

### Negative

- `CursorConnectionCubit` grows — monitor ~300 line class limit; extract private helpers if needed.

### Risks

- State object complexity — use focused enums and clear `copyWith` resets when modal opens.

## Implementation Notes

Call `resetSettingsSession()` when the sheet opens. On successful save/remove, call `runPreflight()` to refresh banner/review gate.
