# ADR-003: Test-Gated Save with Draft Credential Validation

## Status

Accepted

## Date

2026-05-22

## Context

`RunCursorConnectionPreflightUseCase` only validates the key already persisted in `CursorCredentialStoreService`. Admins must test a pasted key before save without persisting invalid secrets. Product chose: Save persists only after a successful **Test connection** in the same modal session.

## Decision

1. Add `ValidateCursorCredentialUseCase` (and `CursorPrdAgentService.preflightCredential(String apiKey)`) that calls `GET /v1/me` using the draft key without writing to secure storage.
2. Add `SaveCursorCredentialUseCase` that writes to the store, then relies on `CursorConnectionCubit.runPreflight()` (or internal preflight) to set global connection status.
3. Extend `CursorConnectionCubit` with session flag `isTestPassedForDraft` (reset when modal opens or draft text changes). **Save** is enabled only when the flag is true and draft is non-empty.
4. **Test** sets the flag on success; clears it on failure or draft edit.

## Alternatives Considered

### Alternative 1: Save always triggers validation

- **Description**: Save button runs preflight after write; no explicit test gate.
- **Pros**: One button path.
- **Cons**: Persists before validation unless rolled back; weaker alignment with admin “test first” UX.
- **Why rejected**: User selected test-required-before-save.

### Alternative 2: Save without validation

- **Description**: Persist immediately; test optional.
- **Pros**: Simplest code.
- **Cons**: Violates PRD validation goals.
- **Why rejected**: Unacceptable for MVP.

### Alternative 3: Temporary write + rollback for test

- **Description**: Write to secure storage for test, restore on cancel.
- **Pros**: Reuses preflight unchanged.
- **Cons**: Side effects on failed tests; race if app crashes mid-test.
- **Why rejected**: Inferior to explicit draft validation API.

## Consequences

### Positive

- Invalid keys never touch secure storage.
- Same HTTP check as production preflight mapping.

### Negative

- New service method and use case; HTTP client needs credential override for one request.

### Risks

- Auth header logic duplication — centralize Basic auth encoding in a small private helper shared by HTTP client and draft validation.

## Implementation Notes

Do not store draft API keys in cubit state for `toString`/logging; keep draft in `TextEditingController` in the sheet widget only.
