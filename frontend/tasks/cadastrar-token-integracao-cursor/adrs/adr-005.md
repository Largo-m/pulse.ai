# ADR-005: Confirmation Dialog Before Credential Removal

## Status

Accepted

## Date

2026-05-22

## Context

Removing the stored API key immediately blocks PRD approval and shows the connection banner. Accidental taps on **Remove** would disrupt the team without recovery friction beyond re-paste.

## Decision

Show a confirmation `AlertDialog` (same pattern as `PrdReviewUnsavedOverwriteDialog`) before calling `RemoveCursorCredentialUseCase`. On confirm: delete from secure storage, reset session test flag, run `runPreflight()`, close settings sheet optional (stay open showing disconnected state — prefer close sheet and let banner guide).

## Alternatives Considered

### Alternative 1: Immediate remove

- **Description**: No dialog.
- **Pros**: Fewer clicks.
- **Cons**: Easy mis-tap; PRD recommends confirmation.
- **Why rejected**: User selected confirm dialog.

### Alternative 2: Confirm only when connected

- **Description**: Skip dialog if already disconnected.
- **Pros**: Less noise when remove is idempotent.
- **Cons**: Edge case complexity for little gain.
- **Why rejected**: User chose unconditional confirm dialog.

## Consequences

### Positive

- Aligns with PRD secondary flow; matches existing dialog conventions.

### Negative

- Additional PT-BR strings and unit/widget-adjacent tests for dialog labels.

### Risks

- None significant.

## Implementation Notes

Add `CursorIntegrationRemoveConfirmDialog` with strings in `OrchestratorStrings` (or `cursor_integration_settings_strings.dart` if split — prefer extending `OrchestratorStrings` group for cursor settings to avoid file sprawl unless class exceeds maintainability).
