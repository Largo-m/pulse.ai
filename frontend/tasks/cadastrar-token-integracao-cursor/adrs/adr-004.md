# ADR-004: Connection Banner Visible for Disconnected and Failure

## Status

Accepted

## Date

2026-05-22

## Context

`CursorConnectionBannerPolicy.shouldShow` returns true only for `CursorConnectionStatus.disconnected`. Preflight maps 401 and network errors to `failure`, so admins with an invalid stored key see no banner—only review/start remediation strings. PRD requires discoverability when credentials are missing or invalid.

## Decision

Update `CursorConnectionBannerPolicy.shouldShow` to return true for `disconnected` **and** `failure`. Keep banner hidden for `initial`, `checking`, and `connected`. Continue using `state.remediationMessage` for banner body copy (missing vs. unauthorized vs. network).

## Alternatives Considered

### Alternative 1: Banner only when disconnected

- **Description**: Leave current policy.
- **Pros**: No code change.
- **Cons**: Invalid stored keys lack top-of-workspace CTA to settings.
- **Why rejected**: User selected expand banner for failure states.

### Alternative 2: Banner + persistent connected chip in top bar

- **Description**: Show subtle connected indicator when healthy.
- **Pros**: Positive feedback.
- **Cons**: PRD Phase 2; extra chrome work.
- **Why rejected**: Deferred; MVP expands failure visibility only.

## Consequences

### Positive

- Invalid and network states gain the same “Abrir configurações” CTA as missing key.

### Negative

- Banner may show more often until admin fixes or removes key — intentional.

### Risks

- Copy must distinguish error types — already on `CursorConnectionState.remediationMessage`; add strings tests when new copy is added.
